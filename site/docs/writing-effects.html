Write an effect

An effect is a Rust static with metadata and a spawn function. This page shows its parts, the drawing API, the rules that keep it deterministic, and how to register and test it.

Anatomy

Effects may use procedural paint, authored sprite frames or both. Use Painter::sprite for straight-alpha RGBA8 frames in local coordinates. Embed the frames with include_bytes! and select them in Rust at the effect's frame rate. Set Effect::render_kind() to Sprite or Hybrid when the effect ships authored frames. See Rune Flash for a hybrid.

Effects live in crates/pixfx-effects/src/<category>/<name>.rs. The skeleton below follows feedback/outline.rs:

use std::sync::Arc;

use pixfx_core::{Actor, Area, Effect, EffectState, Layer, Meta, NumOpt, Options, Silhouette};
use pixfx_draw::Painter;
use pixfx_draw::color::Rgba;

pub struct Rim;
pub static RIM: Rim = Rim;

const WIDTH: NumOpt = NumOpt::new("width", 1.0).within(1.0, 3.0); // an option of its own, held to a range
const META: Meta = Meta {
    id: "feedback/rim",
    name: "Rim",
    desc: "A light pulsing round the sprite it wraps.",
    tags: &["feedback", "outline", "light", "character", "loop"],
    size: (128, 128), // room for the sprite and its glow on every side of the origin
    origin: (64, 64), // the point that lands where the caller plays it
    duration: 2.0,    // seconds per loop (or of the one-shot)
    looping: true,
    fps: 30,
    seed: 1,
    state: None,
    options: &[WIDTH.spec()],
};
const PALETTE: [Rgba; 2] = [Rgba::hex24(0x3a62e0), Rgba::hex24(0x7fb4ff)];

impl Effect for Rim {
    fn meta(&self) -> &Meta {
        &META
    }
    fn wraps_actor(&self) -> bool {
        true // the scene hands it the sprite it plays on, every frame
    }
    fn spawn(&self, opts: &Options, _seed: u64) -> Box<dyn EffectState> {
        Box::new(State { ramp: opts.palette_or(&PALETTE), width: opts.num(&WIDTH) as u32, ring: Vec::new() })
    }
}

struct State {
    ramp: Vec<Rgba>,
    width: u32,
    /// The cells round the sprite as it is now; none without one.
    ring: Vec<(i32, i32)>,
}

impl EffectState for State {
    fn set_actor(&mut self, actor: Option<Arc<Actor>>) {
        self.ring = actor.map_or_else(Vec::new, |a| {
            let pad = self.width as i32;
            let area = Area { x: a.x() - pad, y: a.y() - pad, w: a.w() + 2 * self.width, h: a.h() + 2 * self.width };
            Silhouette::of(&a, area).ring(self.width, false).collect()
        });
    }
    fn draw(&self, p: &mut Painter, t: f64, layer: Layer) {
        if layer != Layer::Back {
            return; // off the body: the sprite drawn over it hides none of it
        }
        // 0..1, one period per `duration` (2 s), so the loop closes exactly
        let k = 0.5 + 0.5 * libm::sin(t * core::f64::consts::PI);
        let Some(&c) = self.ramp.get(usize::from(k > 0.5)) else {
            return;
        };
        for &(x, y) in &self.ring {
            p.px(f64::from(x), f64::from(y), c);
            p.glow(f64::from(x), f64::from(y), 3.0, c, 0.3 * k); // light is additive, drawn into the light layer
        }
    }
}

Draw in local space: (0, 0) is the effect's origin, y grows downward. The instance places, mirrors and rotates the painter before calling draw, and applies fade-out and the light option, so the effect never handles them.

Draw from time, or simulate

Most effects draw purely from t (seconds into the loop) and the seed, so any frame can be drawn on its own and loops close exactly. Effects with real physics (sparks that bounce, debris that settles) keep state and override EffectState::update(dt), which the instance calls once per sub-step of at most 1/120 s.

The painter

Painter (crates/pixfx-draw/src/painter.rs) draws into the frame's two layers. All coordinates are local and may be fractional; shapes snap to whole pixels.

MethodDraws
px, dot, blendOne pixel: opaque; at an alpha faded by ordered dither; or translucent.
line, rect, ellipse, tri, polyFilled shapes and 1 px lines. Colour and alpha can be constants or functions of the shape's own coordinates.
each, shadeVisit every pixel in a local box and decide its colour and light yourself. Every filled shape is built on each, so shapes mirror and rotate exactly.
glow, glow_line, glow_ringLight only: radial glow falling as (1 − d)² to 0 at radius r, along a line, or round a ring.
put, add, blend_pxWrite colour or add light at a screen pixel.

Code two effects of a category share goes in that category's lib.rs; code every effect can use goes down to pixfx-draw or pixfx-core.

Rules

These keep native and wasm builds bit-identical and are enforced by the compiler and clippy:

  • No platform float math. clippy.toml disallows f64::sin, sqrt, floor, round and every other transcendental, rounding or fused method. Use libm::*, and pixfx_draw::math::js_round where JavaScript would call Math.round.
  • Randomness comes from the seed. Use math::rand, hash, noise or a seeded Rng, never a system random source or the clock.
  • No panics. unwrap, expect and panic are denied; handle a missing value (let Some(..) else { return }).
  • No unsafe. Every crate has #![forbid(unsafe_code)].
  • Ports keep pixelfx's semantics. Where JavaScript behaves differently from Rust (NaN in Math.min, | 0 truncation, Uint8ClampedArray rounding), use the math::js_* and to_int32/to_uint32 helpers.

Register it

Each effect has its own cargo feature, the id with / as -, so a game builds only the effects it plays. tests/features.rs fails if one of these is missing:

  1. In the category's mod.rs (for example src/feedback/mod.rs): #[cfg(feature = "feedback-rim")] mod rim; and #[cfg(feature = "feedback-rim")] pub use rim::RIM;.
  2. In crates/pixfx-effects/Cargo.toml: feedback-rim = [], and add it to its category feature (feedback), which is in all.
  3. In crates/pixfx-effects/src/lib.rs: #[cfg(feature = "feedback-rim")] &feedback::RIM, in EFFECTS. The order there is the order effects() returns.

Check once with every effect built: cargo test -p pixfx-effects --test features. Every renderer, the scripts and the JS shells pick it up from the registry; nothing else needs changing.

Test it

Build and test the effect alone, behind its feature, so nothing else compiles or runs:

cargo test -p pixfx-effects --no-default-features --features feedback-rim --all-targets
PIXFX_BLESS=1 cargo test -p pixfx-effects --no-default-features --features feedback-rim --test determinism -- --ignored
cargo test -p pixfx-effects --no-default-features --features feedback-rim --test determinism -- --ignored
cargo run -p pixfx-export --example gif -- feedback/rim --scale 4
cargo run --release -p pixfx-effects --no-default-features --features feedback-rim --example bench
  1. Look at the gif (target/out/feedback_rim.gif) before you bless: blessing records what is drawn, right or wrong. Blessing with one effect built rewrites only its entry in tests/goldens/frame_hashes.json.
  2. A change shared by many effects (pixfx-core, pixfx-draw, a category's lib.rs) runs the same tests without the feature flags, and the wasm check once: wasm-pack test --node crates/pixfx-effects --test determinism -- --include-ignored.
