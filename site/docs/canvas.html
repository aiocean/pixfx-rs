Canvas renderer

pixfx-canvas draws effects onto an HTML canvas with Canvas 2D. Mount a Stage, say which effects play where, and either let it run its own loop or drive it from yours.

Build

wasm-pack build crates/pixfx-canvas --target web --out-dir pkg

Ship pkg/pixfx_canvas.js and pkg/pixfx_canvas_bg.wasm together and serve them over HTTP. The module also exports the JS engine's effects(), meta(id) and Fx, so one wasm file covers both.

import init, { Stage, effects, meta } from "./pkg/pixfx_canvas.js";
await init();

Self-running stage

For a page that only shows effects:

const canvas = document.querySelector("canvas");
canvas.width = 320 * 4;
canvas.height = 180 * 4;

const stage = new Stage(canvas, 4);
stage.background("#13101b");
const fire = stage.play("fire/campfire", 160, 160, { seed: 3 });
stage.start();

// later
stage.stop(fire);   // fades out, then removes itself
stage.pause();      // effects keep their state; start() resumes

Each frame the stage clears the canvas (or fills the background colour), then draws the back layer of every effect, then the front layer of every effect, oldest first. Time is the real time between animation frames.

Set image-rendering: pixelated on the canvas if CSS resizes it, so the browser keeps the pixels sharp.

Host-owned loop

A game that draws its own sprites between an effect's layers owns the loop. Call update(dt), draw your ground, drawLayer("back"), draw your sprites, then drawLayer("front"). drawLayer never clears and leaves the context's compositing and smoothing as you had them.

const SCALE = 4;
const stage = new Stage(canvas, SCALE);
const ctx = canvas.getContext("2d");
stage.play("fire/campfire", 168, 160, { seed: 1 });

let last = null;
function frame(now) {
  const dt = last === null ? 0 : Math.max(0, now - last) / 1000;
  last = now;
  stage.update(dt);
  ctx.fillStyle = "#17131c";
  ctx.fillRect(0, 0, canvas.width, canvas.height);
  stage.drawLayer("back");
  drawPlayer(ctx);            // your sprites, in canvas pixels (game pixels × SCALE)
  stage.drawLayer("front");
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);

tick(dt) is update(dt) plus a full draw (clear or fill, back, front), for a host that owns the loop but draws nothing between layers.

Cues and feel

Some effects fire cues at the frame of their impact: a camera shake, a hit-stop, a screen ripple, a flash or a sound. By default the stage answers them itself with its Feel. A hit-stop freezes its effects, and its own loop (start, tick) shakes the view and lifts it toward white. Sounds are always the host's to play.

A host-owned loop freezes with the effects by advancing its own world by what update returns, and moves its view by shake:

const played = stage.update(dt);   // 0 during a hit-stop, a fraction in slow motion
world.step(played);
const [dx, dy] = stage.shake(settings.shake);   // game pixels; 0 holds the view still
ctx.save();
ctx.translate(dx * SCALE, dy * SCALE);
// ground, drawLayer("back"), sprites, drawLayer("front")
ctx.restore();
for (const e of stage.events()) {
  if (e.type === "cue" && e.cue.type === "sound") audio.play(e.cue.name, e.pan);
}

A host with its own answer (a Phaser camera, say) calls setFeel(false) and reads the cue events. The stage then plays every second update gives it, and shake, flash and ripples stay empty.

API

new Stage(canvas, scale)

Draw onto canvas (an HTMLCanvasElement), one game pixel as scale×scale canvas pixels. scale must be at least 1. Throws if the canvas has no 2D context, for example because it already has a WebGL one.

play(id, x, y, opts?) → handle

Play effect id with its origin at game pixel (x, y), rounded to a whole pixel. Returns a numeric handle; handles start at 1 and are never reused. opts takes the common options and the effect's own. Throws on an unknown id, a bad option, a non-finite position, or a margin option (the stage sizes each effect's margin itself, as meta.glowMargin).

stop(handle)

Let the effect end: loops fade out over 0.3 s, one-shots are cut short. It is removed once done. Unknown handles are ignored.

move(handle, x, y)

Move the effect's origin to game pixel (x, y), rounded to a whole pixel, without restarting it: for an effect that follows the pointer or a sprite. Unknown handles are ignored; a non-finite position throws.

const wisp = stage.play("critters/wisp", 0, 0);
addEventListener("pointermove", (e) => stage.move(wisp, e.offsetX / SCALE, e.offsetY / SCALE));

set(handle, change)

Change where and how the effect draws without restarting it: {x?, y?, flip?, angle?, light?}. Each key left out keeps its value; x/y are game pixels, rounded as move does, and angle is radians. An unknown key, a wrong type or a non-finite number throws; unknown handles are ignored.

events() → StageEvent[]

What happened since the last call, oldest first; the queue is emptied. {type: "end", handle} for each effect that finished, faded out after stop, or was removed. {type: "cue", handle, t, pan, cue} for each cue an effect fired, t seconds into its playback, with pan from -1 to 1 across the stage. cue.type is one of:

  • "shake": {trauma}, 0 to 1
  • "hitstop": {dur} seconds of freeze
  • "ripple": {x, y, r0, r1, dur, amp}, a ring growing from r0 to r1 game pixels
  • "flash": {k, dur}
  • "sound": {name, gain, pitch, len, x}; len caps its length in seconds, or is null

setFeel(on)

true (the default): the stage answers cues, as described in Cues and feel. false: the host answers them from the cue events.

shake(strength) → [dx, dy]

Where the view sits this frame, in whole game pixels, from the trauma the cues and addTrauma built up. strength is the player's setting: 1 as designed, 0 holds the view still.

roll(strength) → radians

How far the view tilts this frame (positive is clockwise), for a host that draws the stage into a view it can rotate. The stage's own loop leaves it out to keep the pixel grid.

setShakeStrength(strength)

How hard the stage's own loop shakes the view: 1 as designed (the default), 0 not at all.

trauma(), flash(), frozen(), ripples()

How shaken the view is (0 to 1), how white it is lifted (0 to 1), whether a hit-stop freezes play now, and the screen ripples alive now as {x, y, r0, r1, dur, amp, age} in game pixels and seconds. The stage's own loop applies shake and flash; ripples are for a host that bends its view.

addTrauma(k), freeze(secs), slow(secs, speed)

The game's own impacts, answered like cues. addTrauma adds k (0 to 1) to the shake. freeze is a hit-stop of secs seconds; freezes do not add up, the longest wins. slow plays at speed (0 to 1) of real time for the next secs seconds, after any freeze. They do nothing while setFeel(false).

remove(handle)

Drop the effect now. Unknown handles are ignored.

start() and pause()

start() runs the stage's own requestAnimationFrame loop; calling it while running does nothing. The first frame after start() steps 0 s. pause() stops the loop; effects keep their state. If a frame fails, the loop logs pixfx Stage stopped: ... to the console and stops; pause() then start() retries.

update(dt), drawLayer(layer), tick(dt)

For host-owned loops, as above. dt is seconds, a finite number, 0 or more; anything else throws and changes nothing. layer is "back" or "front". update removes effects that are done.

setScale(scale)

Change game pixel to canvas pixels (at least 1). Resize the canvas yourself to match.

background(css)

Fill the canvas with this CSS colour before each tick or self-run frame. "" clears to transparent instead (the default). Has no effect on drawLayer.

handles()

The playing handles, oldest first. Finished effects are gone.

free()

Release the stage's wasm memory (generated by wasm-bindgen). Freeing a running stage stops its loop.

How it draws

Each effect has its own small OffscreenCanvas and pixel buffer, made once when it is played and reused every frame. For each layer, the colour half is drawn with source-over, then the light half with "lighter" (additive, saturating), each enlarged by scale with image smoothing off. Empty halves are skipped. Every effect gets glowMargin pixels of room round its canvas and no edge fade, so glow shows in full.

Light is drawn as light over transparency: it adds exactly its light to an opaque canvas, and shows as that light's colour on a transparent one.

The decisions (placement, ordering, removal, the pixels of each layer) are plain Rust in crates/pixfx-canvas/src/stage.rs, tested natively; lib.rs only blits.
