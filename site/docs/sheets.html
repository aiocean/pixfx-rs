Sprite sheet format

What the sprite_sheet script writes: three PNGs laid out on one grid, and a JSON file that Aseprite-style loaders and beanfx both read.

Layout

Every frame is one cell of the same size, the effect's canvas (meta.size, or the size its options give, as outline's w and h, plus twice the margin; the scripts use margin 0). Cells go left to right, at most 8 per row, then down.

EffectCellFramesGridSheet size
projectiles/trail160×16088×11280×160
feedback/power-up160×1441818×231280×3312

A loop has round(duration × fps) frames; frame i is the effect after i steps of 1/fps, so the last frame leads back into the first. A one-shot has one more frame, its last moment.

The three images

  • <name>.png (RGBA): colour with light added, over transparency, as composite makes it. Draw it normally when your engine cannot blend additively. It reads correctly over dark backgrounds.
  • <name>_color.png (RGBA, straight alpha): the colour layer only. Draw it normally.
  • <name>_light.png (RGB): the light layer only. Draw it over the colour with additive blending (src + dst). Black adds nothing.

Drawing _color then _light additively gives the effect exactly as the live renderers show it, lighting whatever is under it.

JSON

The JSON follows Aseprite's "array" export, so Aseprite loaders (Phaser's load.aseprite, many others) read it, with beanfx's own fields under meta.beanfx. Abridged output for projectiles/trail:

{
  "frames": [
    {
      "filename": "projectiles_trail 0",
      "frame": { "x": 0, "y": 0, "w": 160, "h": 160 },
      "rotated": false,
      "trimmed": false,
      "spriteSourceSize": { "x": 0, "y": 0, "w": 160, "h": 160 },
      "sourceSize": { "w": 160, "h": 160 },
      "duration": 33
    }
    // ... one entry per frame
  ],
  "meta": {
    "app": "pixfx",
    "version": "1",
    "image": "projectiles_trail.png",
    "format": "RGBA8888",
    "size": { "w": 1280, "h": 160 },
    "scale": "1",
    "frameTags": [{ "name": "projectiles_trail", "from": 0, "to": 7, "direction": "forward" }],
    "beanfx": {
      "name": "projectiles_trail",
      "fps": 30,
      "frames": 8,
      "rows": 1,
      "frameSize": [160, 160],
      "columns": 8,
      "pivot": [80, 80],
      "loop": true,
      "end": "loop",
      "sheet": "projectiles_trail.png",
      "color": "projectiles_trail_color.png",
      "light": "projectiles_trail_light.png",
      "blend_light": "add",
      "light_gain": 1.0
    }
  }
}

Fields

FieldMeaning
frames[].durationMilliseconds per frame, round(1000 / fps).
frames[].frameThe cell on the sheet. Cells are never trimmed or rotated.
meta.frameTagsOne tag spanning every frame, named after the effect.
beanfx.pivotThe effect's origin within a cell, y down from the cell's top-left: the origin on its canvas plus the margin (meta.origin + margin unless its options size the canvas). Place this point where the effect should stand.
beanfx.loop, beanfx.endtrue and "loop" for loops; false and "remove" for one-shots, which should be removed after the last frame.
beanfx.sheet, color, lightFile names of the three images, relative to the JSON.
beanfx.blend_light, light_gainDraw light with additive blending at gain 1.
beanfx.rowsAlways 1: pixfx writes one animation per sheet. The grid's own row count is ceil(frames / columns).
